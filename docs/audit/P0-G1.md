## 已实现的局部能力

- 控制库和数据面写连接使用 `internal/sqlitepolicy` 的逐物理连接钩子，验证 SQLite 版本和 source ID，设置并读回 busy timeout、外键、WAL 和 FULL；不合格即拒绝连接。仅版本门槛与 source ID 非空不能证明构建供应链或断电行为。拒绝有副作用的 DSN 参数和不支持 WAL 的内存数据库。
- 临时配置 `server.edition: enterprise` 会在服务装配及可写 CLI 访问数据库之前拒绝执行；缺省 `legacy` 保持上游路径。当前该限制也拒绝 Enterprise DNS 服务，尚未达到目标可用性。它仅约束显式选择 Enterprise 的当前命令，不能防止修改配置、其他进程直接访问数据库或代替 fencing；迁移状态及 HA 状态是只读诊断例外。
- `internal/enterprise/ipamaddr` 实现地址和 CIDR 编码及严格解析；`internal/enterprise/ipamgap` 提供有界区间首个缺口算法。二者是独立基础包，尚未接入现有 API。
- `internal/enterprise/ipamstore` 在独立空库安装固定摘要的参考 IPAM DDL，或将匹配 v1 基线的隔离参考库升级到 v2；前向 002 增加六表 rowid 防护，保留原 001 摘要，并验证迁移回滚和已安装对象。多物理连接争用测试验证单个地址最多一个占用；它不是上游 schema 升级，也不能证明历史数据未丢失。
- `internal/enterprise/rolelog` 验证本机记录的结构与一致性，并在独立目录中通过文件和目录同步及原子替换持久化保守的角色状态。初始化只允许 BOOTSTRAP，普通保存当前只允许不变或同 epoch 转 FENCED；不能推进 epoch。`internal/enterprise/rolebarrier` 提供默认关闭的进程内排空原语。它们未接入业务；本机记录无法单独证明外部 fencing、防止整机快照回滚或授予权限。迁移状态检查使用只读连接并剥离 DSN 参数。
- `internal/enterprise/hasign` 验证固定域前缀与 Ed25519 签名的受限 JCS 子集；`internal/enterprise/hapermit` 定义候选接管许可，校验两位不同审批者的签名与可信时间区间，并可核对独立提供的预期身份、锚点、摘要和 nonce。它们不验证 fencing 证据真伪、不消费 nonce、不提供角色授权；许可仍需与运维登记和接管流程集成。
- `internal/enterprise/snapshotpipeline` 串接清单、分块摘要和 NDJSON 有界解析，支持零块、零字节、零行的空快照；回调异常后永久拒绝复用。`snapshotipam` 验证五类业务行、身份账本、STATIC 创建审计与幂等收据的候选行和主键顺序；`snapshotstage` 测试夹具按依赖顺序导入临时数据库，逐键核对来源账本、保留所提供的历史墓碑和已过期收据原始字节，再复验 schema、逐字段、地址池范围及有限跨表关系。收据最大响应可跨块，行上限须显式设为 2 MiB；公开导入、安装入口始终拒绝。该八表候选与旧四表、五表、六表候选即使都标 schema=1 也不兼容，限制 UTF-8 数据库及单项文本长度；不能证明来源账本本身完整，仍缺 DHCP 租约、完整业务审计及其他必要数据，也未验证网关及站点排除策略。DHCP 租约快照不能直接复用旧 `dhcp_leases`（其 TEXT/DATETIME/MAC 模型与候选结构化语义不兼容），须先冻结 Enterprise 租约参考 schema 才能实现（冻结提案见 `contracts/enterprise-dhcp-lease.proposal.md`，含地址表示、状态枚举、过期处理等开放问题，尚未实现代码）；`snapshotipam` 的候选八表顺序与列集合已由 `TestCandidateFormatIsPinned` 固定，防止格式静默漂移。清理失败会报告但不自动重试，物理提交故障和处理中取消尚未验证。成功并不证明完整业务不变量、数据来源或可安装性。
- `internal/enterprise/haregistry` 在隔离数据库中测试发放序号与 nonce 不复用及未决许可互斥；公开变更入口默认拒绝，尚未接入审批、fencing、撤销证据或生产登记。
- `internal/enterprise/idempotency` 在调用方事务内保存和查找作用域化收据；封闭中的 `eventlog.WriteTx` 已通过固定 SQL 适配收据、指定地址 STATIC 插入及本地成功审计，绑定请求摘要、规范响应和三个按序排列的占用/审计/收据候选复制变更。隔离夹具验证占用、事件、收据和审计共同提交及故障回滚。`dhcpwire` 解析受限 DHCPv4 客户端报文、Option 61 和未经认证的 Option 82；隔离入口映射及纯编码器测试按匹配条件原样回显。`dhcptx` 的私有夹具验证租约、候选事件、outbox、XID 收据和 head 的同事务提交。真实 relay 身份验证、实际发包、可信时间、持久时间水位和生产授权仍未接入，模拟 COMMIT 故障不代表物理断电测试。目标分配路由接入了现有认证、权限和访问审计链，合法请求固定返回 503；该关闭状态不约束仍存在的旧版分配入口。发送侧候选编码不代表已复制或可接管。
- `internal/enterprise/trustedtime` 提供需注入可信时源和单调时钟的保守状态机，`internal/enterprise/timewater` 提供本机高水位持久化；`internal/enterprise/timeguard` 在返回时间边界前确认持久水位。调用方仍需认证时源、处理休眠/重启，并接入实际门禁。`internal/enterprise/httpcontract` 提供独立强 ETag 解析，尚未接入 API。
- `internal/enterprise/ipamevent` 和 `contracts/enterprise-ipam-occupancy-v1.md` 定义独立占用事件候选 schema；`staticbundle` 和 `replicabatch` 验证原始事件链与候选变更，`replicaapply` 私有测试夹具验证多事件业务投影、日志和 head 在一个事务提交及故障回滚。该夹具仅允许最多 16 条、拒绝批次重放，低于正式协议范围。`eventlog.ReadSnapshot` 可在同一读快照返回候选前缀和观测 head，检查已读取事件、锚点和 head 的同 epoch leader 一致性，不证明权威尾部或前缀后的整段链；`eventlogguard.InspectTx` 与 `ReadSnapshotTx` 可由调用方在同一只读事务组合，私有 `replicaread` 夹具进一步验证完整 protobuf 预算，公开入口仍拒绝。已固定复制 proto、生成 Go/gRPC 类型，并由 `pullresponse` 离线构造新消息及验证最终 protobuf 编码预算；仅测试编译的 `replicarpc` 回环 mTLS 夹具在证书和请求检查后于同一只读事务组合加固 schema、事件读取与 protobuf 预算；真实回环覆盖双向证书及公钥 pin、同 CA 同 SAN 异钥拒绝和认证失败前不读库。`peeridentity.VerifyHandshake` 供 TLS 握手回调验证服务端证书，测试覆盖客户端 TLS 1.3 会话恢复后重新检查 pin 和时间；身份不证明角色或可信时间。`pullresponse.BuildControl` 仅离线编码 `EPOCH_REBASE_REQUIRED` 和 `SCHEMA_INCOMPATIBLE` 两个控制候选，要求调用方提供未认证的观测 head 与真实下一条事件，不推断来源或授权；RPC 夹具在跨 epoch 时以同事务自校验的本地 head 及与测试预期 leader 比对后发出前者，在真实下一条 v1 事件不可读时发出后者，AT_HEAD 无 v1 保守拒绝。`SNAPSHOT_REQUIRED` 与 `DIVERGED` 尚无构造路径，普通存储错误或取消不会被映射为链分叉；这些分类仍缺独立角色/epoch/fencing 权威证据。公开启动始终拒绝。`peeridentity`、`replicaguard`、`replicaschema` 和 `pullbudget` 分别提供独立的证书绑定、持久隔离、结构校验及预算原语，尚未装配到生产复制应用。夹具对压缩请求的拒绝发生在 gRPC 解压后，不能证明解压前防护或撤权后的网络排空；最终网络传输仍需检查消息未知字段、压缩策略和 wire 上限。公开应用入口默认拒绝；真实 TLS 通道和角色绑定、隔离恢复、生产 schema、真实断电/未知提交和迁移尚未完成。隔离测试已复现 eventlog 候选的 audit、receipt、event、head 与 checkpoint 表可被具有任意 SQL 写能力的调用者通过隐藏 rowid 和 REPLACE 替换旧行；`eventlogguard` 提供单一只读快照内的旧版/加固版本机参考结构识别，以及只接受加固版的验证；核对固定 schema、marker、连接策略及有限行约束，识别旧版不代表可写，且该结构版本不等于事件、快照或 RPC 版本；测试夹具可在精确匹配的旧参考库上原子安装 rowid、逻辑键与部分键类型守卫，八表暂存夹具也验证了独立构造的加固版空库。公开迁移仍拒绝，现有 schema 未被生产升级，现有结构不构成防篡改边界。新版参考结构会被现有 `replicaschema` 拒绝，且新增逻辑键守卫会拒绝同键 UPSERT，后续集成必须处理版本和写路径兼容；只读验证不授予角色或保证后续库状态。`internal/enterprise/dhcpholds` 仅在隔离空测试库原型中对 IPv4 DHCP 占用和 IPAM 占用设置双向冲突守卫；未覆盖实际数据面迁移、租约来源、池清退、可信释放和生产旁路关闭。
- `internal/enterprise/dnssnapshot` 是纯内存快照原语；`dnswire` 与 `dnsanswer` 提供隔离的 A/AAAA/NS/SOA 候选快照、只读应答、受限 EDNS 和 UDP 截断，不支持委派、通配符、CNAME、传送或递归。`dnstransport` 仅在包内 fixture 上验证回环 UDP/TCP 与关闭后排空，公开 Start 默认拒绝，源 CIDR 不证明客户端身份。`soaserial` 提供 RFC 1982 算术，`soalineage` 在隔离事务中记录谱系；`generationpointer` 仅提供绑定身份和摘要的世代记录只读检查，公开安装与切换拒绝。它们尚未接入生产 DNS 网络服务、身份认证、授权或持久发布；谱系集成须独立保证全局 view 唯一及 zone 规范化。
- `internal/enterprise/eventlog` 提供原始字节散列封套、向量及严格载荷校验。事件类型和业务 body 仍需按实际业务合同完成和审定。当前缺少独立角色日志、签名授权与 fencing，受保护写事务入口及 peer 确认入口明确拒绝，不能用于生产写入或接管。

## round 121 增量：`pullresponse` 控制候选补齐

此前 "`SNAPSHOT_REQUIRED` 与 `DIVERGED` 尚无构造路径" 已收敛为**离线构造路径**（`internal/enterprise/pullresponse/control.go` + `control_snapshot_test.go`）：
- `ControlInput` 新增 `Earliest`/`Conflict` 两个显式证据事件；`BuildControl` 现在编码 4 种控制处置（`EPOCH_REBASE_REQUIRED` / `SCHEMA_INCOMPATIBLE` / `SNAPSHOT_REQUIRED` / `DIVERGED`）。
- `SNAPSHOT_REQUIRED` 要求同 epoch、`After.Seq < Head.Seq`、`Earliest` 是保留窗口中最早事件且 `Earliest.Seq > After.Seq+1`（批次无法跨过的缺口），事件本地摘要有效、cluster/leader/schema 一致；`DIVERGED` 要求 `Conflict` 与 `After` 处于同一 (epoch, seq) 但摘要不同。两者都禁止同时提供其他证据。
- 证据校验会 clone 后再 `Verify()`，不修改调用方数据；无证据 / 摘要不符 / 身份不符 / 跨 epoch / 位置越界等 30 组反例全部 `ErrInvalid`。
- **边界未变**：编码器不读库、不接受错误参数、不从存储错误推断分叉；提供合法证据**不是**独立角色/epoch/fencing 权威，也不是权威尾证明、快照安装许可或生产授权。公开启动、复制/快照安装与受保护写仍恒 `ErrNoAuthority`；`README.md` 已同步。
