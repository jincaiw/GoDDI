# DNS candidate snapshot format v0

This is an isolated candidate format for tests and future review. It is not a complete DNS configuration, DNS wire protocol, authentication mechanism, authorization decision, durable release, or production-ready authoritative server. In particular it contains no ACLs, compiler version, view priority, compatibility manifest, indexes, delegation/glue semantics, publication receipt, signature, or revocation control. It only represents IN-class A, AAAA, NS, and SOA; CNAME, wildcard names and all other types are rejected. No source authenticity is implied by SHA-256.

The canonical byte representation is compact JSON with the exact object field order emitted by the package and UTF-8 encoding. Decoding accepts only bytes equal to the canonical encoding: alternate order, whitespace, escapes, duplicate/unknown/missing fields, invalid Unicode, and trailing content are rejected. The SHA-256 is computed on those exact bytes. Limits are 1 MiB, 128 zones and 8192 records total, with bounded field lengths. Version is a positive decimal string within signed 63-bit range; checking monotonicity requires external persisted state.

`cluster`, `node`, and `snapshot` are non-nil canonical lowercase UUIDs. `view` is 1–128 lowercase ASCII letters, digits, dot, underscore or hyphen. `zones` sort by name; records sort by owner, type, then RDATA, all lexicographically. Zone/owner/NS/SOA names are lowercase absolute ASCII FQDNs using letters, digits, underscore and hyphen, each label 1–63 bytes, total wire length at most 255 bytes; the root is `.`. Wildcards are rejected. Each owner must lie at or below its zone. All names must already be IDNA-processed externally; this format does not perform IDNA conversion.

RDATA for A/AAAA is the canonical `netip` textual IP without a zone or IPv4-mapped IPv6. NS is an absolute canonical name. SOA is exactly `mname rname serial refresh retry expire minimum`, with single ASCII spaces, canonical names and unsigned decimal uint32 numbers with no leading zeros. Its serial equals the zone's serial. Exactly one SOA and at least one NS must be at the apex. TTL is 0 through 2^31−1; records in an RRset have identical TTL and identical records are rejected.

`Build` canonicalizes ordering but rejects invalid semantic values. `Decode` requires canonical bytes and retains a private immutable copy; accessors return copies. Neither authenticates the identities or authorizes a snapshot. Callers must independently validate and persist the release, verify approvals and monotonic version/serial history, close and drain revoked network paths, and enforce all DNS protocol behavior before any integration.
