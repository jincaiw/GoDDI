# DHCP transaction fixture

This isolated prototype is not a DHCP allocator or network handler. Public Begin and Commit always return ErrNoAuthority. No socket, role barrier, fencing, external peer, trusted clock, DHCP options, IPAM occupancy, ACL, production schema migration or receiver apply is implemented. Fixture input scope, address and time are test assertions, not trusted facts. Time is checked against the current head and the instance's most recently observed time, but no trusted clock or durable anti-rollback watermark exists. Its returned value is test data, never a network reply.

A test-only schema and explicit cluster/node, scope and head support a pinned SQLite `BEGIN IMMEDIATE`: lease, eventlog V1 candidate envelope, local outbox, XID receipt and CAS head commit atomically. The unfrozen candidate event body is version 2 (distinct from the event envelope schema version) and includes client identity and request-stage fields; it is incompatible with earlier fixture bodies. A production format must make its privacy and replication contract explicit. Actual receiver apply does not exist.

Retry digest covers stable tenant, space, lease ID, client key, XID, message kind and address, not server time. Replay requires the fixture's simulated current time strictly before original expiration, an exact matching current lease, and the original event and outbox at the current independently supplied head; it never extends expiration. Older events cannot be replayed until a verified historical-chain protocol is designed. OFFER cannot replace a still-live OFFER or ACK; an exact retry uses its receipt. After expiry a new OFFER may establish a new XID. A selecting ACK requires a still-live OFFER with the same XID and a matching current-head event; an ACK already committed can be replayed only with a matching receipt, while INIT_REBOOT or RENEW_REBIND may use a different XID after current lease, head event and outbox are independently matched. The original OFFER XID is bound to the current lease and event on replay. This is not a full DHCP state machine or proof of safe transmission.

The injected commit error tests model errors before and after SQLite COMMIT; they are not physical storage or power-loss experiments. On an ambiguous result, the instance stops and returns no reply; the transaction may have committed, so recovery must verify durable state independently.
