# Isolated IPAM staging checks

`Check` requires a dedicated SQLite connection with `PRAGMA query_only=ON` and `foreign_keys=ON`, an independently verified manifest's exact four table counts, and explicit row and decoded value byte caps. It starts one read transaction, runs `integrity_check(1)` and `foreign_key_check`, reads bounded and typed values, applies snapshotipam's candidate row validation, and checks scopes, prefix parents and siblings, and occupancy subnet/family/range and address uniqueness. Standard subnet network addresses, and IPv4 broadcast addresses, are rejected as in the reference trigger. Counts must match exactly even when zero.

The caller must provide an isolated staging database and guarantee no concurrent use of this connection, no other writers, and a reviewed, locked schema throughout the call. The package does not inspect or authenticate the schema, and `query_only` is only connection-local. PRAGMA integrity and foreign key checks may scan other tables; row and byte limits cover the four table projections, not total database pages or wall-clock execution. The caller must use an appropriate deadline and bound the database file independently. No database rows are modified.

Evidence contains only named checks; it does not establish a complete snapshot or installation readiness. In particular it does not prove ledger completeness, slug uniqueness independently of the controlled schema, pools, leases, DHCP safety, audit, receipts, role authority, fencing, or global chain continuity. Schema validation and safe snapshot installation remain separate prerequisites.
